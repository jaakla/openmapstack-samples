# Source assessment — Tartu PV pilot

Checked 26 October 2026 against live provider metadata and actual bounded responses. The project uses the GitHub `main` OpenMapStack discovery guidance; source snapshots and immutable SHA-256 pins are in `sources.lock.json`. The pilot is a **4 km²** square in EPSG:3301, `[658125,6472170,660125,6474170]`, near Tartu centre. It is a reproducible planning demonstration; these inputs do not establish installation-level inventory accuracy or measured production accuracy.

## Time and units

Open-Meteo documents GHI, DNI and DHI as **preceding-hour means**. Acquisition requests include the following year's first midnight. The normalization subtracts one hour from each provider timestamp and selects interval starts within the requested year. Solar position should be evaluated at the interval midpoint. Temperature is the provider value at interval end. No weather values are filled or synthesized.

GHI sums are 1,014.793 kWh/m² for 2024 and 946.826 kWh/m² for 2025. Raw prices include the requested endpoint inclusively; the normalization excludes the first hour of the following year. Normalized annual rows match complete UTC calendars, independent of Estonia daylight-saving changes. The market data are hourly during 2024 and mixed hourly/quarter-hourly during 2025. Hourly mean prices do not preserve covariance between within-hour cloud changes and quarter-hour prices.

## Surface quality

Both GeoTIFFs have exactly the same transform `(658125,5,0,6474170,0,-5)`, CRS and 400×400 dimensions. There is no array flip or half-cell shift. Raw service responses do not declare a nodata value, but the DSM contains 658 nonpositive cells. Those are marked unknown in the normalized grid. Another 360 positive cells have DSM more than 2 m below the aligned DTM; a documented conservative plausibility filter marks those unknown too. The threshold is a processing assumption, not an official source classification. **1,018 of 160,000 DSM cells are unknown**; DTM has none under this rule. Raw GeoTIFFs remain unchanged.

Different source dates, interpolation around data holes and a coarse surface grid limit local shading accuracy. In particular, narrow trees, new construction, seasonal leaf state, individual panels, rack geometry and roof planes are not resolved reliably at 5 m. A DSM is a surface envelope, not a classification into buildings and trees. No invented tree objects are added.

The supplied geometry is hypothetical. A visually inspected low-relief roadside/parking strip near `[26.7148,58.36891]` provides an open-ground example; visual inspection of this rendered image establishes neither land availability nor suitability for construction.

## Government access result

The actual published layers are:

- Existing solar counts: `https://services.arcgis.com/fe2zzRbhcPNuoFC4/arcgis/rest/services/Taastuvenergiarajatised_liigiti_KOVides/FeatureServer/14`, field `Päikeseja`.
- Planned solar counts: `https://services.arcgis.com/fe2zzRbhcPNuoFC4/arcgis/rest/services/Kavandatavad_taastuvenergiarajatised_liigiti_KOVides/FeatureServer/16`, field `Päikeseel`.

The retained query asks `KOV LIKE '%Tartu%'` and omits geometry because these are aggregates. It returns two municipalities without a transfer-limit flag. Existing counts are 21 for Tartu linn and 81 for Tartu vald; planned counts are 7 and 40. These apply to the whole municipalities, **not the 4 km² pilot**. No capacity value in these records is treated as installed DC kWp. Installation-level status/date fields are absent. Public ArcGIS item `licenseInfo` is empty: no CC licence has been inferred.

The wider provider description covers existing and planned ground-mounted parks and cites multiple upstream sources. That does not establish rooftop completeness or guarantee that an individual-record endpoint is available through this particular application. Municipal counts must not be converted into fabricated PV sites.

## Inventory and validation status

The official rendered orthophoto was independently inspected as planning context, including a roadside/parking candidate away from the map centre. No model inference, native-resolution AOI-wide inventory or individual-module counting has been performed. The map therefore makes no model-detection or inventory recall claim. No training/held-out labels or installation-level precision/recall metrics are fabricated.

To complete issue #4's inventory extension, obtain dated native orthophotos through the [provider download catalogue](https://geoportaal.maaruum.ee/est/ruumiandmed/ortofotod/laadi-ortofotod-alla-p610.html), pin model/code/weights licences and checkpoints, tile the entire AOI independently of government records, and manually label geographically separated validation regions including small rooftops and negative backgrounds. Then reconcile real array polygons with installation-level records if those can be obtained. Keep source counts, model observations and physical parameter assumptions separate. The original owner-provided 15-minute production series is also absent and remains necessary for local production validation.

## WeatherNext 3

The [Google DeepMind page](https://deepmind.google/science/weathernext/) and [Google developer documentation](https://developers.google.com/weathernext/) were checked because the issue specifically suggests this source. Current documentation describes hourly-initialized operational ensemble forecasts and access to current/historical forecasts through Cloud Storage, Earth Engine and BigQuery. It mentions radiation and cloud-cover variables. No WeatherNext bytes, authenticated access, complete 2024/2025 site history, or product-specific radiation timestamp semantics were verified in this implementation. WeatherNext is therefore a future forecast-provider integration, not an unsubstantiated substitute for the pinned ERA5 history. Its radiation/cloud variables would still need validation against the existing input contract and site measurements.

## Retention and reuse

Maa- ja Ruumiamet's [open-data licence](https://geoportaal.maaruum.ee/avaandmete-litsents) permits redistribution and derivatives with provider/dataset/date attribution and a licence link. Its [service terms](https://geoportaal.maaruum.ee/est/teenused/wms-wfs-wcs-teenused/maa-ja-ruumiameti-kaarditeenuste-kasutustingimused-p24.html) were also checked. Map attribution uses the provider name and extraction date. The bounded acquisition performs two coverage requests, one building query and one display image request; it does not scrape nationwide imagery.

[Open-Meteo terms](https://open-meteo.com/en/terms) specify CC BY 4.0 for data; free API access is restricted to non-commercial use. Elering's dashboard/API and the ArcGIS government items did not expose an explicit dataset reuse licence in the checked metadata, so those licence fields remain unresolved rather than invented. Source rights are distinct from the repository's code licence.

`python3 acquire.py` verifies every retained snapshot/derivative without network access. `python3 acquire.py --normalize` reproduces normalized weather, prices, grids and building context from pinned raw inputs and verifies byte-identical hashes. `--refresh` explicitly downloads mutable source responses and writes new pins; it is an input update, not an exact rerun of the original provider responses. Raw JSON/XML responses use deterministic gzip with zero mtime. Reproduction of the original analysis uses the committed local snapshots, not a promise that a provider's mutable “latest” response will remain unchanged.
